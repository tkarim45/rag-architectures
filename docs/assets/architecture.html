RAG Architectures — Architecture

13 RAG architectures, one corpus, one labeled eval set, engineered as a real framework and measured side by side. Each is a self-contained production-style package on a shared core, so score differences are architecture differences.

One core, so the comparison is honest

  • • typed domain models, pluggable LLM / embedding / vector-store backends, retry and caching, span tracing, structured-output repair
  • • every architecture runs over the same documents, the same embeddings and the same LLM under a strict fairness contract: one shared generator prompt, one shared judge, shared offline artifacts
  • • the eval is a fully FICTIONAL interlinked knowledge base (14 docs about invented companies and products) plus 12 labeled questions with gold doc ids
  • • fictional on purpose, so a method only scores if it actually retrieves the right docs: this measures RAG, not memorization
  • • 43 offline tests run with no keys, no network and no model downloads

Five families, thirteen packages, each grounded in its paper

  • • retrieval: naive dense top-k, BM25 sparse, hybrid with RRF or weighted fusion, cross-encoder rerank
  • • query transform: multi-query rephrasing, RAG-fusion, HyDE
  • • indexing: sentence-window, parent-child and contextual chunking
  • • structural: GraphRAG with Louvain communities, RAPTOR with recursive summaries
  • • control flow: corrective (CRAG), adaptive complexity routing, agentic ReAct loop

Multi-hop is the discriminator, and rephrasing does not solve it

  • • the query-transform methods and the naive baseline all scored 0% on multi-hop: no rephrasing of "who founded the company behind X" resembles the founder document
  • • the winners add a second MECHANISM rather than more lexical breadth: follow-up searches (agentic 83%/50%), cross-doc summary nodes (raptor 83%/50%), or more context per hit (hybrid with parent-child chunking 75%/50%)
  • • GraphRAG underperformed its promise at this scale (67%/25%) because traversal reaches bridge docs but extraction quality and a 2-hop limit gate it: graph quality IS extraction quality
  • • corrective RAG helps precision, not hops (50%/0%): grading catches bad retrieval, but a rewrite still cannot reach a bridge doc
  • • caveat: 12 questions plus an LLM judge means one flipped question moves a method about 8 points, so the robust signal is structural rather than the exact ranking
